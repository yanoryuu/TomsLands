# 実況動画の調査メモと3本の設計方針（2026-10-26）

ずんだもん × 四国めたんの掛け合いで「トコのトムトムランド」の10分前後・横動画を3本作る。
作る前に「どんな動画が伸びているか」「どんなサムネが伸びているか」を調べ、3つの軸ごとに型を決めた。
ゆっくり実況の型（顔の表情切替・話者色の字幕・ネタ画像の差し込み・テロップ・効果音）を土台にする。

## 1. 伸びている動画の傾向（調べた範囲）

| 傾向 | 根拠 | この企画でどう使うか |
|---|---|---|
| 1本の中に「1つの物語」を収める。投稿頻度が高い。システム説明は少なめで攻略はある | ゲーミングボーイ分析（X の視聴者メモ）[^gb1] | A（淡々）は「1ラン＝1話」で完結させる。説明は最小限 |
| 作業量を抑え、演出に凝らない。字幕はハードサブ＋プレーンな字幕ファイルも用意 | ゲーミングボーイ本人の note [^gb2] | 字幕は焼き込み＋ SRT を別出力 |
| 情報を並べるだけ・似た構成は伸びにくい。ストーリー性と感情の流れ、ずんだもんの「動き・ツッコミ」が価値 | ずんだもん動画の運営記事・個人ブログ [^z1] [^z2] | B（解説）でも「結論→仕組み→実演で証明」の物語にする。C（プレイ）はリアクションとツッコミを主役にする |
| 解説をずんだもんの声→字幕＋効果音に替えたら伸びが落ちた（1事例） | 個人ブログ [^z2] | 3本とも全編に声を乗せる |
| ゆっくり実況は「後から台本を練れる」ので、ネタ・ツッコミ・画像の差し込みが詰まっているのが強み。テンポの良い編集、ユーモアのあるコメント | マイナビ・ニコニコ大百科 [^yk1] [^yk2] | 喋っている内容に合わせて差し込み画像（ネタ画像・ミーム・ゲーム内の絵）を切り替える。表情は顔アイコンで切り替える |
| 長編ゲーム実況は10分以上・16:9 が標準 | Clipchamp [^cc] | 10分前後・1920×1080 |

ゲーミングボーイさんのチャンネルは「無名インディーを1本の物語として淡々と遊ぶ」型。
その型の肝は **一話完結・説明を削る・テンポ・乾いた一言** の4つと読んだ。

## 2. 伸びているサムネの傾向（調べた範囲）

| 傾向 | 根拠 |
|---|---|
| 画面を分割しない。ゲームキャラを出す。文字は画面の1/3以内。フォントは1種類。色数を絞る。テンプレを統一 | カムイトラッカー調査（再生10万以上のゲーム動画、2021–22）[^kt] |
| 録画実況・まとめ系は投稿者の顔なし、キャラ2名以上、スクショ＋キャラ切り抜きが約73% | 同上 |
| 攻略系はキャラ1名で情報量を抑える | 同上 |
| 1280×720、キャッチは短く（15文字以内）、縁取りで埋もれさせない、背景・メイン文字・アクセントの3色 | サムネ解説記事 [^s1] [^s2] [^s3] |
| 「神回」「衝撃の結末」のような短い煽りテロップを目立つ色で | [^s4] |
| ゲームロゴや立ち絵の上に文字を重ねない | ゆっくり実況のサムネ記事 [^y1] |

→ 3本とも **同じテンプレ**（背景＝ゲーム画面か公式キービジュアル、右にキャラ、左に2行の大文字、フォント1種、3色）で、文字と色だけ軸ごとに変える。

## 3. 差し込み画像の方針（ゆっくり実況の型）

| 種類 | 作り方 | 例 |
|---|---|---|
| ネタ画像（イラスト） | 画像生成で「太い線のフラットなステッカー風・文字なし・背景透過」に統一 | お金の雨、空の財布、サイコロ、号外、暴落グラフ、督促状、水晶玉、赤スパ、ひらめき、ドラゴン |
| ミーム（文字カード） | Pillow で描く（色カード＋太字＋少し傾ける）。権利物の画像は使わない | 草 / ｷﾀ━━(ﾟ∀ﾟ)━━!! / 完 / ｵﾜﾀ / ざわ…ざわ… / ドヤァ / ※諸説あります / はい解散 / な、なんだってー！！ |
| ゲーム内の絵 | プロジェクトの素材をそのまま | 勇者・魔王・鍛冶屋の立ち絵、タイトル絵、地図 |
| 表情 | VOICEVOX のスタイル別アイコン（ノーマル／あまあま／ツンツン／なみだめ…）を字幕の横に出し、セリフの感情で切り替える | — |

画像は **そのセリフの間だけ** 画面上部に出し、次の画像で入れ替える（ポンと出る動き＋効果音）。

## 4. 3本の設計

| | A 淡々プレイ（ゲーミングボーイ型） | B 解説動画 | C 普通のプレイ動画 |
|---|---|---|---|
| 物語 | 1ラン（かんたん＝8日・配信2回）を初日から決着まで | 「このゲームは投機ゲーム」という結論を、仕組み3つ→実演で証明 | 初見で遊んで、配信の決着で一喜一憂 |
| 役割 | ずんだもん＝操作・淡々、めたん＝相方で短く補足 | めたん＝解説役、ずんだもん＝初心者の聞き役・ツッコミ | 2人とも感情多め。ずんだもんが賭けて、めたんが止める／煽る |
| 説明量 | 最小 | 多い（章カード・キーワードテロップ） | 中（遊びながら自然に） |
| 間 | 多い（無言のプレイ区間を残す） | ほぼ無い | 少ない |
| 差し込み画像 | 少なめ（乾いた一言に1枚） | 図解寄り（グラフ・新聞・督促状） | 多め（ミーム多用） |
| 声の調子 | ノーマル中心 | ノーマル中心、要点だけツンツン | あまあま／ツンツン／なみだめなど幅広く |
| 冒頭30秒 | 「結果から言うと◯◯」→本編へ | 「このゲーム、経営じゃなくて賭けです」と結論 | 一番盛り上がる場面の先出し（配信の決着） |
| BGM | 通常営業（小さめ） | 通常営業→配信フェーズ | 配信フェーズ多め |

共通の核は **読み → 賭け → 的中 → 大儲け**（配信は賭けが決着する場。勇者側にも魔王側にも張れる）。
3本とも「賭けた → 配信で決着 → 儲けた／溶けた」の因果が映像で伝わる順にする。

## 6. 制作フロー（YouTuber の流れに寄せる）

1. 企画・調査（このメモ）
2. 台本（`scripts/*.json`。話者・感情・間・差し込み画像・章ごとの必要素材を書く）
3. 素材づくり（ネタ画像の生成・ミームカード・ゲーム内の絵の切り出し）
4. 撮影（Unity: Tools/TomsLands/自動録画/実況動画用に録画して Play。初回ランをラン終了まで等速で撮る）
5. 素材の割り当て（`footage.json` に、章ごとの素材ファイルと開始秒・配信の勝ち負けを書く）
6. 音声（VOICEVOX ずんだもん・四国めたん。`jikkyo.py voice`）
7. 編集・書き出し（立ち絵・顔アイコン・字幕・差し込み画像・章カード・効果音・BGM。`jikkyo.py render`）
8. サムネ（`jikkyo.py thumb`）
9. 投稿情報（タイトル・説明文・タグは台本の `youtube` に入れてある。クレジット「VOICEVOX:ずんだもん」「VOICEVOX:四国めたん」必須）
