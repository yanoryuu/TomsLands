## 2. 推理の前提（相性表）

ダンジョンの `requiredAttribute`（DungeonIndoData/*.asset）と `items_sheet.tsv` の防具の説明文から作った表。
**L1 の武器の属性と L2 の防具の属性は、どのダンジョンでも同じになる**（コードの `ApplyTargetRule` もそうなっている）。

| 敵の属性（攻撃） | 弱点 = L1 の武器 | 防ぐ = L2 の防具 | 該当するダンジョン |
|---|---|---|---|
| 火 | 水 | 水（水流の鎧＝火を無効） | 灼熱の火山牢 |
| 水（氷） | 土 | 土（岩石の鎧＝水を弾く） | 氷霧の洞窟 |
| 風 | 火 | 火（炎のたすき＝風を焼き払う） | 深緑の獣林 |
| 土 | 風 | 風（疾風の鎧＝土を受け流す） | （なし。岩の巨兵などダンジョン外の事象で使う） |
| 闇 | 光 | 光（聖光の鎧＝闇を受け止める） | 忘却の霊廟・魔王城 |
| 光 | 闇 | 闇（暗黒の兜＝光を受け流す） | 古代機構城メタリオン |

**書き分けの約束**: 武器（L1）は「刃が通らない・決め手を欠く・弱みを突く得物・斬り払う・叩き割る」、
防具（L2）は「負傷・受け止めきれない・身を守る・身を固める・身支度・着ていく」。
L3 は「格上・懐が温かい・上の格の品・値の張る品」。

## 5. Jev 検証の結果（2026-10-08・Docs/News_Phase3_Spec.md §8）

### 6.3 誤報の手がかり（loud の統一）

誤報になりうる事象（全事象が false>0）の loud テンプレート 26本を同じ型にそろえた。

- clarity は全て `anonymous`（署名の有無は社の `bylineRate` が決める。かわら版 0.3）
- リードは必ず「〜という話だ。」で終える
- 本文は「誰が見たのか分からない／出どころは定かでない」を入れ、証言者・場所などの具体を書かない（属性の手がかりは残す）

### 6.4 残る確認点

- 分割で事象の ID が変わった（例 `EV_HERO_EXPEDITION` → `EV_HERO_EXPEDITION_VOLCANO` など）。Jev の再検証と、旧 ID を前提にしたコード・テストが無いかの確認が要る
- 事象の `cooldown` は ID ごとなので、分割した系統は「別のダンジョンが次になったとき」に元より早く再登場しうる。気になる場合はコード側で「系統」単位の cooldown を足す
- 代わりの案: コードに「次ダンジョンの魔物の性質」を差し込む枠（例 `{foe}`）を足せば、分割せず元の7事象に戻せる
