# 1. Unity作業手順

## 🔴 A. 通常フェーズ4分割（TomsShopシーン）

ターン進行を「イベント→仕入れ→商品陳列→営業」の順次フェーズへ再構成済み。
同じShopホーム内で、現フェーズのボタングループだけを表示する設計。

### A-1. ボタンを3グループに再配置
TomsShopシーンの既存ボタンを、新規の空GameObject（グループ親）の子に移動する。

- **空GameObjectを3つ作成**（Shopホームのパネル配下）
  - `procurementGroup`（仕入れ）
  - `displayGroup`（商品陳列）
  - `salesGroup`（営業）
- 既存ボタンを以下のように振り分けて子にする：

| グループ | 含めるボタン |
| --- | --- |
| procurementGroup（仕入れ） | 情報屋 / 鍛冶屋 / 道具屋 / ダンジョンLv / 広告 / ヒーロー / マップ |
| displayGroup（商品陳列） | 陳列設定 / 預言者 / 需要ダッシュボード |
| salesGroup（営業） | 営業開始（`StartShopButton`） |
| グループ外（常時表示） | 借金返済ボタン（`debtPaymentButton`）・メニュー・所持金/ターン表示 |

> ⚠️ 旧 **「次のターン」ボタン（NextTurnButton）は削除**。コードからは参照を除去済みなので、シーン上のGameObjectを消すだけ。

### A-2. TurnPhaseView を配置
- Shopホームのパネルに **空GameObject＋`TurnPhaseView` コンポーネント** を追加
- フェーズ表示ラベル（TMP）と「次へ／スキップ」ボタンのUIを新規作成
- `TurnPhaseView` のInspectorに割当：

| フィールド（Inspector表示） | 割り当てるもの |
| --- | --- |
| Phase Label | フェーズ名表示の TextMeshProUGUI |
| Advance Button | 「次へ」ボタン |
| Procurement Group | A-1の procurementGroup |
| Display Group | A-1の displayGroup |
| Sales Group | A-1の salesGroup |

### A-3. SalesPhaseView を配置（営業の簡易演出）
- 空GameObject＋ **`SalesPhaseView`** を追加
- Inspector（すべて任意・未設定でも進行する）：
  - `Overlay`：演出用 CanvasGroup（暗転や光）
  - `Coin Icon`：弾むコインの RectTransform
  - `Duration`：演出長（既定0.8秒）

### A-4. GameLifetimeScope に参照を割当
TomsShopシーンの `GameLifetimeScope` のInspectorに追加：

| フィールド | 割り当て |
| --- | --- |
| Turn Phase View | A-2の TurnPhaseView |
| Sales Phase View | A-3の SalesPhaseView |

### A-5. 動作確認
- 新ターン → イベント（無ければ自動で仕入れへ）→「次へ」で 仕入れ→陳列→営業
- 各フェーズで該当グループのボタンだけ表示される
- 詳細画面（鍛冶屋など）を閉じると同じフェーズのホームに戻る
- 営業フェーズ：「営業開始」→簡易演出→売上サマリー→確認→次ターン
- ヒント（TurnActionHint）が現フェーズの画面のみ提案する

## 🔴 B. リモートコンフィグ＋ローディング（Bootシーン新規）

起動時にサーバーから調整値を取得して `GameConst` に適用 → タイトルへ遷移する。

### B-1. Bootシーンを新規作成
- 例：`Assets/Scenes/Boot.unity`
- 空GameObjectに **`BootLifetimeScope`** を付与
  - `Enable Remote Config`：ON（既定）
  - `Remote Config Url`：本番URL（既定で設定済み）
  - `Remote Config Timeout Sec`：10（既定）

### B-2. ローディングUIを作成
- Canvas（全画面）に：
  - **全画面 CanvasGroup**（フェードアウト用）
  - **スピナー画像**（回転するローディングアイコン）
  - **ステータステキスト**（TMP、「設定を確認中...」表示用）
- そのCanvasに **`LoadingView`** を付与し割当：

| フィールド | 割り当て |
| --- | --- |
| Canvas Group | 全画面CanvasGroup |
| Spinner | スピナーの RectTransform |
| Status Text | ステータスTMP |
| Spinner Speed | 180（既定・度/秒） |
| Fade Out Duration | 0.3（既定） |

- `BootLifetimeScope` の **`Loading View`** に、このLoadingViewを割当

### B-3. Build Settings
- **`Boot` シーンを先頭（index 0）** に配置
- `TitleScene` もビルド対象に含まれていることを確認
- 遷移先名は `"TitleScene"` 固定（異なる場合は `LoadingPresenter.NextSceneName` を変更）

### B-4. 動作確認
- 通常起動：ローディング → タイトル → 本編がサーバー値
- オフライン：ローディング →（キャッシュ→デフォルト）でタイトルへ（固まらない）
- `Enable Remote Config` OFF：取得スキップで即タイトルへ

## 🟡 C. ゲームフロー自動生成（推奨）

### C-1. GameConstSettings アセット
- `GameConstSettings.asset` の `flowGeneration` を調整
  - 各モード（Short/Medium/Long）の `dungeonCount` / Shopターン数 / `eventRate`
  - `dungeonWeights`（ダンジョン別出現率）
  - `randomSeed`（0=毎回ランダム／非0=固定）
- 既存アセットはデフォルト自動補完されるため必須ではない

### C-2. タイトルUI（任意）
TitleScene の `TitleView` に割当（未割当でも「自動・Short」で動作）：

| フィールド | 割り当て |
| --- | --- |
| Auto Generation Toggle | 自動/手動トグル |
| Short Mode Button | 短時間モードボタン |
| Medium Mode Button | 中時間モードボタン |
| Long Mode Button | 長時間モードボタン |

---

## 🟡 D. 所持金カウントアップ（任意）
- `CommonView` の `Money Count Duration`（既定0.5秒）を必要なら調整

## ⚪ 共通
- 再コンパイルして Console にエラーが無いこと（新規スクリプトの .meta は自動生成）
- 新規スクリプト：`TurnPhaseView` / `SalesPhaseView` / `LoadingView` / `BootLifetimeScope` / `TurnPhaseManager` ほか

### シーン別・触るコンポーネント早見表
| シーン | 作業内容 |
| --- | --- |
| Boot（新規） | BootLifetimeScope, LoadingView, ローディングUI |

| TomsShop | ボタン3グループ再配置, TurnPhaseView, SalesPhaseView, GameLifetimeScope参照割当, NextTurnButton削除 |

# 2. 画面ブラッシュアップ用 画像生成プロンプト（ChatGPT用）

> 使い方：まず下の「共通スタイル指定」をコピーし、各画面プロンプトの先頭に貼り付けて生成すると、
> ゲーム全体のトンマナが揃った参考画像になります。出力は **UIモックアップ（参考デザイン）** が目的です。

## 共通スタイル指定（各プロンプトの先頭に付ける）

```
あなたはゲームUIデザイナーです。スマホ/Steam向け「お店経営＋RPG」ゲームの
UIモックアップ（参考デザイン）を1枚の画像として生成してください。

ゲーム概要: 主人公トムが武器・防具屋を経営し、勇者がダンジョンへ挑む。
雰囲気は「温かみのあるファンタジーの雑貨店／鍛冶屋」。かわいい看板娘キャラ「トコ」が中心。
アートトーン: 木目・羊皮紙・暖色（琥珀/茶/クリーム）を基調に、ファンタジーRPGの装飾枠。
親しみやすくポップだが安っぽくない。日本のソーシャルゲーム品質のUI。
画面比率: 16:9 横長。テキストはダミーの日本語でよい。
清潔でゲームに実装可能なレイアウト。余白と階層が明確。
```

---

### ① ローディング画面（Boot）
```
（共通スタイル指定を貼る）

画面: 起動時のローディング画面。
構成: 中央にゲームロゴ（架空のファンタジー店名ロゴ）、その下に回転するローディング
スピナー、さらに下に「設定を確認中...」の小さなステータステキスト。背景は店内の
ぼかし or 夜の街並みの暖かい灯り。下部に小さくバージョン表記。
シンプルで上品、待ち時間が心地よく感じる雰囲気。
```

### ② タイトル画面（モード選択つき）
```
（共通スタイル指定を貼る）

画面: タイトル画面。
構成: 中央〜左に大きなタイトルロゴと看板娘キャラ「トコ」の立ち絵。
右側〜下部に縦並びのメインボタン「はじめから」「つづきから」。
さらに「ゲームモード選択（短い旅 / ふつうの旅 / 長い旅 の3択トグル）」と
「フロー自動生成 ON/OFF トグル」を、わかりやすい小さめのUIブロックとして配置。
ローグライト感のある冒険のワクワク感。
```

### ③ 通常フェーズ（4分割の進行UI）
```
（共通スタイル指定を貼る）

画面: お店経営のメイン画面。1ターンが「イベント→仕入れ→商品陳列→営業」の
4フェーズで順番に進む。
構成:
- 上部に「フェーズ進行バー」: イベント / 仕入れ / 商品陳列 / 営業 の4ステップを
  横並びで表示し、現在のフェーズをハイライト。
- 中央に店内の様子と看板娘キャラ。
- 現在フェーズ（例: 仕入れ）に応じたアクションボタン群を画面下に表示
  （仕入れ: 情報屋/鍛冶屋/道具屋/ダンジョン強化/広告/勇者装備/マップ）。
- 右下に大きな「次へ」ボタン。
- 上部に所持金（例: 1,234,567G）とターン数の表示。
順番に進めるガイド付きの分かりやすいフロー。
```

### ④ 商品陳列フェーズ
```
（共通スタイル指定を貼る）

画面: 「商品陳列フェーズ」。棚に商品を並べる画面。
構成: 中央に店の陳列棚（複数スロット）、左に手持ち商品リスト（ドラッグで配置できそうな見た目）、
右に「需要ダッシュボード（どの商品が今売れるかのグラフ/トレンド）」と「預言者（売れ筋ランキング）」の
情報パネル。下部に「次へ（営業へ）」ボタン。
経営シミュレーションらしい、情報を見て判断するレイアウト。
```

### ⑤ 営業フェーズ（射倖心のある売上演出）
```
（共通スタイル指定を貼る）

画面: 「営業フェーズ」。お店が自動で商品を売る様子の演出画面。
構成: 中央で商品が次々売れ、コインが飛び散るエフェクト。売上金額が大きく
カウントアップ表示（例: +1,234,567G）。画面全体に高揚感のある光・パーティクル。
パチンコの大当たりのような段階的な盛り上がり。最後に「ターン評価（S/A/B…）」の
リザルトパネルが出る。射倖心を煽る派手で気持ちいい演出。
```

### ⑥（参考）バズ中演出 ※ロードマップ先取り
```
（共通スタイル指定を貼る）

画面: お店が「バズっている」最中の通常画面。
通常バズ: 画面のフレーム周囲が金色に光りパルス点滅、コインや星のパーティクル。
大バズ: フレームが虹色のグラデーションアニメーション、パーティクルがさらに増加。
通常時との差別化が一目でわかる、テンションの上がる演出。同じ画面の
「通常 / 通常バズ / 大バズ」3段階の比較として並べてもよい。
```

## メモ
- 生成画像は「実装の参考（トンマナ・レイアウト確認用）」であり、そのまま素材にする想定ではない。
- キャラ「トコ」や店名ロゴは仮。確定デザインがあればプロンプトに差し替える。
- バズ演出（⑥）は今後の実装予定項目（ロードマップ参照）。
