# 価格変動 v2 設計 — 2層モデル

作成: 2026-09-20 / 対象ブランチ: feature/jev-market-sim
前提: `Docs/Market_Simulation.md`（v1 の経緯・実測・落とし穴）

---

## 0. 結論

価格を **「適正値」と「その周りの相場」の2層** に分ける。

```
価格 = 適正値(需要から決まる・決定論)  ×  相場の揺らぎ(仮想トレーダー・確率的)
       ───────── 層1 ─────────        ────────── 層2 ──────────
       ゲームのルールを担う             チャートの質感を担う
       設計者が手で決める               お手本に合わせて自動調整する
```

v1 は層2しか無く、適正値が基準価格に固定されていた。そのため需要がいくら動いても価格の**方向**が変わらず、陳列・バズ・広告ステータスが価格に波及しない（需要×リターン相関: Legacy +0.106 / v1 ABM −0.005）。v2 はここを直す。

---

## 1. v1 の問題（実測に基づく）

| # | 問題 | 実測 |
|---|---|---|
| 1 | 適正値が `basePrice` 固定で、需要が価格の方向に効かない | 需要×リターン相関 −0.005（Legacy は +0.106、高需要で +1.9%/ターン） |
| 2 | パラメータ過多（15個）で最適化が変な角へ落ちる | `demandGain` が 0 に最適化され需要watcherが消滅 |
| 3 | Switcher アーキタイプの効果が未検証 | 当初の好成績は端数吸収バグの産物だった |
| 4 | セーブ/ロードで乱数ストリーム位置が飛ぶ | ロード直後の数ターンが本来と違う系列になる |
| 5 | 板の厚みが在庫に比例していた | **解決済み**（stockDepthWeight=0） |

## 2. 設計原則

1. **ゲームのルールは層1に、質感は層2に。** 層1は決定論で設計者が手で決める。層2だけを Jev のお手本にキャリブレーションする。
2. **需要が唯一のファンダメンタルズ。** 既存の全イベント（下表）は需要を動かす。需要→適正値→価格の1本を通せば全部が価格に届く。新しい配線は作らない。
3. **Legacy は無傷。** `LegacyShopPriceEngine` は触らず、既定のまま。
4. **検証できないものは入れない。** Switcher は削除する。
5. **ハーネスは実ランタイム型。** 独自シミュレータで評価しない（v1 で符号が逆になった）。

### 需要を動かす既存の入口（すべて層1経由で価格へ届く）

| 入口 | 場所 |
|---|---|
| 品出し陳列（D2） | `ItemModel.ApplyShopTurnEconomy` |
| 戦闘結果の属性波及（D1） | `ItemModel` 272行付近 |
| 鑑定ブースト | `GameLifecycleHandler` 192行 |
| マシン（冷蔵ケース等）の需要下限 | `ApplyShopTurnEconomy` の `machineDemandFloorBonus` |
| 広告 Spread（品出し効果の増幅）/ Followers（需要下限） | `ApplyShopTurnEconomy` Step1〜2 |
| 流行度 Trend の自然収束 | `ApplyShopTurnEconomy` |

## 3. 層1: 適正値（ファンダメンタルズ）

```
fairValue = clamp( basePrice × (1 + p × (demand − 0.5) × 2),  floor, ceiling )
   p = demandPricePremium（既定 0.5・Inspector）
   floor / ceiling = 既存のストップ安/高（Trust による Floor 底上げ込み）
```

| 需要 | 適正値（p=0.5） | 意味 |
|---|---|---|
| 1.00 | 1.50× | 大人気。上限3.0×には届かない（張り付き防止） |
| 0.80 | 1.30× | 人気（Legacy の高需要帯 0.7 以上に相当） |
| 0.50 | 1.00× | 中立 |
| 0.20 | 0.70× | 不人気 |
| 0.05 | 0.55× | 需要下限。下限0.3×には届かない |

- 線形にする理由: Inspector で直感的（「需要0.8で1.3倍」）。対数対称より説明しやすい。
- `p` はバランス調整の唯一のダイヤル。0.3 なら控えめ、0.8 なら需要ゲーム寄り。
- 適正値は**毎ターンの需要から再計算**する。状態を持たない。

### 需要が価格に届く速さ
層2の逆張り勢が適正値へ引き寄せるので、需要が上がると価格は数〜十数ターンかけて新しい適正値へ収束する。Legacy の「+2%/ターンが無限に続く」と違い、**有限の均衡点に着地する**。収束速度は層2の `valueGain` が決める（キャリブレーション対象）。

## 4. 層2: 相場（マーケット）

### 4.1 トレーダー（4+1種）

| アーキタイプ | 見るもの | 役割 | v1 からの変更 |
|---|---|---|---|
| Momentum | 直近リターン | トレンド増幅・バブルの源 | — |
| Contrarian | **適正値**との乖離 | 平均回帰・張り付き防止 | 基準価格→**適正値**へ |
| DemandWatcher | **適正値の変化**（=需要の変化） | 需要変化を先回りして値動きへ変換 | 需要Δ→適正値Δへ。`demandGain` に下限 2 |
| MarketMaker | 直近1ターンの行き過ぎ | 短期ノイズの抑制 | — |
| Noise | 乱数 | 地の揺らぎ | — |
| ~~Switcher~~ | — | — | **削除**（未検証） |

不感帯（参加人数の揺らぎ）・群衆行動・パレート資金分布は維持する。これらがファットテールとクラスタリングの源であることは v1 で実測済み。

**資金分布の制約（実装時に追加）**: パレート分布のまま上限を大きく取ると、編成シード次第で1人が全資金の 40〜56% を握り、その1人の判断が相場の性格を決めてしまう（実測: シードにより σ が 0.003〜0.123 とぶれ、Noise の大口は方向性のない暴れ、MarketMaker の大口は racf1 −0.98 のノコギリ波を生んだ）。対策として (1) `capitalMax` を `capitalMin` の約10倍に抑える、(2) パレート指数 α ≥ 1.5、(3) ノイズ勢（個人投資家）の資金を `capitalMin × noiseCapitalCapRatio`（既定4倍）で別途キャップする。資金テールが尖度に寄与しないことは v1 で実測済み（α 2.8→0.7 で kurt 1.99→2.08）なので、失うものはほぼ無い。

### 4.2 注文 → 価格

```
netOrder  = Σ 注文 / √N                         （人数正規化・v1 と同じ）
depth     = baseDepth × lerp(0.5, 1.0, demand)   （需要による厚みの差を 10倍→2倍 に緩和）
Δlog(P)   = λ × sign(netOrder) × (|netOrder| / depth)^exponent   （exponent ≈ 1.0、平方根則は使わない）
rate      = exp(Δlog) × (fair / price)^anchorPull                （層1の直接の引き寄せ・後述）
          → Attention 上振れ増幅 → Retention 安定化 → ItemModel でクランプ
```

**適正値への直接の引き寄せ `anchorPull`（実装時に追加）**: 当初は逆張り勢の注文だけで適正値へ引き寄せる設計だったが、注文は ±1 で飽和するため、ボラを出そうと λ を上げると引き寄せも一気に強まり、適正値を行き過ぎて翌ターン反転するノコギリ波になった（実測: 最適化が λ を上げるのを拒み、σ が 0.007 で頭打ち）。そこで層1の力を「毎ターン価格を適正値へ k の割合だけ対数空間で寄せる」項として分離した。k < 1 なので原理的に行き過ぎず、長期の張り付きも防げる。これでボラ（λ）と安定性（k）が独立のダイヤルになる。逆張り勢は残すが、役割は補助的になる。

- 在庫は板の厚みに**関与しない**（v1 で修正済み・維持）。
- `depth` の需要レンジを 0.1〜1.0 から 0.5〜1.0 へ狭める。v1 では需要0.05の銘柄が需要0.5の銘柄の10倍動いていた。

### 4.3 乱数と再現性

```
turnRng = new System.Random( Hash(seed, turnIndex) )
seed    = ShopEconomySettings.abmSeed ≠ 0 ? abmSeed : TomsModel.FlowSeed
```

- **毎ターン再シード**する。ターン内の乱数消費は決定論なので、セーブ/ロードを挟んでも同じ系列になる。乱数の位置を保存する必要がない。
- トレーダー編成（資金・不感帯・記憶長）は `seed` から生成し、ターンに依存しない。
- 群衆行動の入力 `lastNetOrder` は非永続（ロード直後は 0）。項が小さいので許容し、保存しない。

## 5. エンジン境界（`IShopPriceEngine`）

v1 の境界を維持し、1点だけ拡張する。

```csharp
void  BeginTurn(int turnIndex);                      // 追加: 毎ターン再シードのため（編成 seed はコンストラクタ）
float GetPriceRate(in ShopPriceContext context);     // 変更なし
```

- `ShopPriceContext` に `FairValue`（層1の計算結果）を追加する。層1は ItemModel 側で計算し、エンジンへ渡す。Legacy は無視する。
- 呼び出し側 `GameFlowManager` は `CurrentTurn.Value` と `TomsModel.FlowSeed` を持っているので、`ApplyShopTurnEconomy` に引き渡す（既定引数で従来呼び出しも壊さない）。

## 7. 検証（実装後に必ず通す）

1. **需要連動**: 需要×リターン相関 ≥ +0.08。高需要帯の平均リターンが正、低需要帯が負。
2. **機能テスト**: 同一銘柄で「陳列 ON」と「OFF」を 60 ターン走らせ、ON の方が高い価格に収束する。
3. **イベント波及**: 需要を +0.3 ジャンプさせた後、価格が新しい適正値へ 15 ターン以内に 80% 収束する。
4. **安全性**: 張り付き 0 / maxDD ≤ 18% / 在庫非依存。
5. **再現性**: 同じ seed・同じ需要系列で、途中でエンジンを破棄→再生成しても価格系列が一致する（セーブ/ロード相当）。
6. **Legacy 不変**: `useAbmPriceEngine=false` で v1 実装と価格系列がビット一致する。

### 需要→価格の意味が変わった点（要認識）

Legacy は「高需要なら毎ターン +1〜3% 上がり続ける」（上限に張り付くまで）。v2 は「高需要なら**高い水準で均衡する**」。収束後は高需要銘柄でも毎ターンの上昇は無い（実測: 高需要帯の平均リターン +0.02%/T ≈ 0）。プレイヤー視点では「需要が上がった瞬間に数ターンで値上がりし、その後は高値で安定」になる。売買の妙味は「需要の変化を先読みする」ことに移る。

### 未達・残課題

- **ボラティリティ・クラスタリング \|r\|acf1 0.077**（目標 0.15〜0.30）。強いアンカー（0.35）は OU 過程に近く、荒れ／凪の持続を弱める。クラスタリングを取りに行くなら anchorPull の上限を下げて再探索するか、需要側に「イベントで一時的にボラを上げる」機構を足す。
- 需要ジャンプ直後に 8% ほど行き過ぎる（DemandWatcher の先回り）。演出としては「話題になった瞬間に一瞬跳ねる」ので許容範囲だが、気になるなら `demandGain` の上限を 15 程度に下げる。
- 探索で `anchorPull` と `impactExponent` が上限に張り付いた。上限を広げれば Loss はさらに下がる余地があるが、anchorPull > 0.35 は「毎ターン1/3以上戻す」で相場らしさが薄れるため意図的に止めている。

## 11. v3: Heat（荒れ具合）による λ 変調 — 2026-09-20

§10 で唯一未達だったボラティリティ・クラスタリング（\|r\|acf1 0.077 / 目標 0.15〜0.30）を解消した。
**同じ仕組みが UI 表示にもそのまま使える**ので、機構を1つ足すだけで両方が片付く。

### 仕組み

```
Heat  = EWMA(|対数リターン|, 半減期 h) を  e/(e+ref)  で 0〜1 へ写像   ← 価格履歴だけから計算
λ_eff = λ × lerp(calmMultiplier, stormMultiplier, Heat)
```

`MarketHeat.Compute(priceHistory)` は**状態を持たない**。`ShopPriceHistory`（セーブ対象・12ターン分）
だけから求まるので、保存対象を増やさず、セーブ/ロードでも一致する。

値動きの**大きさ**にだけ効き、**向き**には効かないので「トレンドが読めてしまう」副作用は出ない
（実測 racf1 −0.044 ≈ 0）。荒れた銘柄はしばらく荒れ、静かな銘柄は静かなまま、が構造的に生まれる。

### 出荷値

| 項目 | 値 |
|---|---|
| `heatHalfLife` | 2.0 ターン |
| `heatReference` | 0.02（1ターン2%の値動きで Heat 0.5） |
| `heatCalmMultiplier` / `heatStormMultiplier` | 0.23 倍 / 4.07 倍 |
| `anchorPull` | 0.22（v2 の 0.35 から低下。Heat が安定性を担うぶん緩められた） |
| `lambda` / `impactExponent` | 1.62 / 1.23 |

### 実測（実コードパス・29銘柄・200ターン）

| | σ | kurt | **\|r\|acf1** | racf1 | maxDD | 張り付き |
|---|---|---|---|---|---|---|
| **v3** | 0.0170 | 4.71 | **0.209** | −0.044 | 15.8% | 0/29 |
| v2（参考） | 0.0190 | 3.85 | 0.077 | 0.122 | 18.0% | 0/29 |
| 目標 | 0.018 | ≥3.5 | 0.15〜0.30 | ≒0 | ≤18% | 0 |

編成シード6種で \|r\|acf1 0.161〜0.228、kurt 4.1〜5.1。**全シードで目標レンジ内。**

§7 の検証はすべて再合格: 陳列ON 1202G / OFF 1003G（適正 1200/1000）、需要ジャンプ 10T で 97% 収束、
在庫 0/5/50/99 で σ 完全一致、60〜400T×6シードで張り付き 0/48、エンジン再生成後も価格系列 0/201 一致。

### UI への出し方

```csharp
float heat  = MarketHeat.Compute(item.ShopPriceHistory);  // 0〜1
string label = MarketHeat.Describe(heat);                 // 凪 / 静か / 平常 / 活況 / 荒れ
Color  color = MarketHeat.ToColor(heat);                  // 青 → 灰 → 赤
int    level = MarketHeat.ToLevel(heat);                  // 0〜4（星・棒グラフ用）
```

引数は価格履歴だけなので、**モデルやエンジンへの参照は不要**。仕入れ画面の銘柄行、価格チャートの
バッジ、詳細パネルのどこからでも呼べる。実測の Heat 分布は 0.15〜0.64（「凪」〜「活況」）で、
5段階のうち中央3段が主に出る。「荒れ」は急変時のみ。

デバッグメニュー（F12 →「相場」タブ）の銘柄一覧に色付きで表示済み。本編 UI もこれを流用すればよい。

### 残課題

なし（§7 の全項目を達成）。以降はプレイして手触りを見る段階。
